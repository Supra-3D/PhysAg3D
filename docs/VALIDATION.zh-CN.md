# 验证范围

源码完整性、环境可用性和生成质量是不同层面的检查。

## 源码与准备目录

`execute.py verify` 检查 `checksums.json` 声明的源文件和源码目录，并检测这些目录中出现的额外文件。本地配置、输入图片、Git 元数据和虚拟环境位于校验范围之外。

`prepare` 复制单张输入、方法文件和结构化配置，记录其哈希，并分配独立远程作业目录。`run` 在执行前检查准备目录是否被修改。新目录和禁用 memory 并不构成操作系统访问隔离；需要独立系统或虚拟机才能检验环境独立性。

## 方法与执行范围

方法包含 `method/assisted_reference_code/` 中明确提供的代码参考。这些实现带有案例相关假设，Worker 需基于新图片与新候选适配，不能以旧资产或固定案例解法替代生成。

主入口采用配置中的订阅执行路线；API 密钥入口独立配置。启动器不自动续跑或重试，执行预算、模型和 native 参数保留在运行记录中。更换模型或参数后，应分别记录实验条件。

## 输出验收

- 比较原图、原始候选和细化结果的轮廓、颜色、纹理与部件归属。
- 检查静止、中间和端点状态下的可见运动，观察枢轴、连接、闭合与穿透。
- 柔性行为需要表面绑定和运动证据，近似形变应明确标注。
- 物理通过需要实际场景、执行记录和报告；动画回放或 GLB 可加载不能替代物理验证。
- 保存失败、部分完成、超时和人工干预，评价时包含全部已启动的案例。

当前工具链的独立机器端到端效果仍待验证；外部依赖及全部辅助模型权重的完整锁定也尚未完成。已有离线测试覆盖准备、参数、错误处理和校验行为，不构成生成质量证明。
